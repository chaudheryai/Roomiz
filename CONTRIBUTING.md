## Git workflow

1. File or pick a GitHub Issue.
2. Create a branch like `feature/update-profile`, `fix/mobile-layout` or `docs/pitch-notes`.
3. Make a small change and test the whole flow.
4. Open a pull request into `main` with one screenshot and a short description.
5. Have one other teammate review it before merging.
6. The live GitHub Pages site updates after the commit to `main` is published.

## Testing checklist

- Landing page works on desktop and phone.
- Dorm profile results are fictional residence-hall profiles.
- Apartment budget filter removes sample candidates over the limit.
- Priorities allow at most 3 selections.
- Request Intro adds a record visible in Demo admin.
- Changing request status works after page refresh.
- Package interest logs to Demo admin without asking for payment information.
- Reset Demo Data clears local profile and requests.

**Never upload real student data or IDs into `data.js` or a GitHub repository.**
